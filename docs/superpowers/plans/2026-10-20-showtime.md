# Showtime Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A free, local-only macOS menu bar app that reads Calendar.app's calendars through EventKit and shows a full-screen alert, with one-click Join, before each meeting. Built with SwiftPM and distributed as a DMG from GitHub Releases.

**Architecture:** Two SwiftPM targets. `ShowtimeCore` is a pure-Swift library with no EventKit/AppKit imports. It holds the models, settings, filters, exclusion rules, meeting-link detection, the alert scheduler and the persisted state, all unit-tested. `Showtime` is the executable. It uses an AppKit app lifecycle (`main.swift` + `NSApplicationDelegate`, `NSStatusItem` + `NSPopover`, an `NSPanel` per screen for alerts, an `NSWindow` for settings), with SwiftUI views hosted inside, an EventKit adapter that maps `EKEvent` → `CalendarEvent`, and Carbon global hotkeys. Shell scripts assemble the `.app` bundle, sign it and make the DMG. GitHub Actions run tests and publish releases.

**Tech Stack:** Swift 6 (language mode 5 is fine if strict concurrency gets in the way), SwiftPM, Swift Testing, SwiftUI + AppKit, EventKit, Carbon (`RegisterEventHotKey`), ServiceManagement (`SMAppService`), `hdiutil`, `codesign`, `notarytool`, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-20-showtime-design.md`. Read it before starting any task.

## Global Constraints

- macOS 14 minimum (`platforms: [.macOS(.v14)]`, `LSMinimumSystemVersion` 14.0). Universal binary (arm64 + x86_64).
- No dependencies outside Apple frameworks. No network calls of any kind.
- Must build and test with Command Line Tools only (no Xcode). Always run tests via `scripts/test.sh`, never bare `swift test`.
- Bundle ID `com.terrythomas.showtime`; display name `Showtime`; `LSUIElement` true.
- Info.plist: `NSCalendarsFullAccessUsageDescription` and `NSCalendarsUsageDescription` = "Showtime reads your calendars to alert you before meetings. Nothing leaves your Mac."
- Entitlements file (used for hardened runtime / notarization): `com.apple.security.personal-information.calendars` = true. No sandbox.
- Read-only calendar access: never call any EventKit save/remove API.
- Don't copy any resource from In Your Face. Sounds come from `/System/Library/Sounds` at runtime.
- Persisted files live in `~/Library/Application Support/Showtime/`; settings live in UserDefaults under key `settings.v1` as JSON.
- Licence: MIT.

## Review Focus

1. **Mac asleep at alert time.** On wake, if the event hasn't ended, the alert shows once and doesn't repeat for the same fire time. → Task 6 test `catchUpAfterSleepShowsOnce`.
2. **Recurring events.** Every occurrence shares `eventIdentifier`. Dismissing Monday's standup must not dismiss Tuesday's. → Task 6 test `occurrencesAreIndependent`.
3. **Exchange/Outlook notes.** Teams links arrive inside HTML, in `<…>` angle brackets, or wrapped in Microsoft SafeLinks (`*.safelinks.protection.outlook.com/?url=<encoded>`). Join must open the real Teams URL. → Task 4 tests `unwrapsSafeLinks`, `findsLinkInsideAngleBrackets`, `findsLinkInHTMLNotes`.
4. **Event moved after being dismissed.** State is keyed by occurrence start, so a rescheduled meeting gets fresh alerts at its new time. → Task 6 test `movedEventAlertsAgain`.
5. **Calendar permission denied or revoked while running.** The menu must show a "Calendar access needed" banner with an "Open System Settings" button, never a silent empty list. → Task 2 test `authorizationBannerState` (pure mapping), and manual check in Task 11.

### Task 6: Handled state and alert scheduler

**Files:** Create `Sources/ShowtimeCore/HandledState.swift`, `AlertScheduler.swift`; Test `Tests/ShowtimeCoreTests/SchedulerTests.swift`

**Interfaces (Produces):**
```swift
public struct OccurrenceState: Codable, Equatable, Sendable { public var dismissed = false; public var snoozedUntil: Date?; public var lastFired: Date?; public var eventEnd: Date }
public struct HandledStateBook: Codable, Equatable, Sendable {
  public var states: [OccurrenceKey: OccurrenceState]
  public mutating func dismiss(_ e: CalendarEvent)
  public mutating func snooze(_ e: CalendarEvent, until: Date)   // clears nothing else
  public mutating func markFired(_ e: CalendarEvent, at: Date)   // lastFired = max(existing, at); clears snoozedUntil if at >= it
  public mutating func prune(now: Date)                          // drop states with eventEnd < now
}
public struct SchedulingContext: Sendable {
  public var settings: ShowtimeSettings; public var overrides: OverrideBook; public var state: HandledStateBook
  public var pausedUntil: Date?   // .distantFuture = indefinitely
  public var calendar: Calendar
}
public struct Evaluation: Equatable, Sendable { public var show: [CalendarEvent]; public var suppressed: [CalendarEvent] }
public enum AlertScheduler {
  public static func fireTimes(for e: CalendarEvent, ctx: SchedulingContext) -> [Date]   // sorted, pending only
  public static func evaluate(events: [CalendarEvent], now: Date, ctx: SchedulingContext) -> Evaluation
  public static func nextFireDate(events: [CalendarEvent], now: Date, ctx: SchedulingContext) -> Date?
}
```
Rules (spec "Alert behavior details"):
- **Base times:**
  - Timed events: `start − offset·60 − (includeTravelTime ? travelTime ?? 0 : 0)` for each offset in `overrides.resolved(for:).alertOffsetsMinutes ?? settings.alertOffsetsMinutes`.
  - All-day events: the single time `allDayAlertMinuteOfDay` on the start day.
  - Then add `snoozedUntil` if it's set.
- **Pending fire times** (what `fireTimes` returns): drop everything if not `EventFilter.isAlertable` or `dismissed`. Drop times ≤ `lastFired`. When `snoozedUntil` is set, drop base times < `snoozedUntil`.
- **evaluate:** skip events with `end <= now`. An event is *due* when some pending time ≤ now. A due event goes to `suppressed` when paused (`pausedUntil > now`) or `!workHours.allows(now)`; otherwise it goes to `show`. Either way the caller calls `markFired(e, at: now)`, which is how a suppressed alert is dropped rather than deferred.
- **nextFireDate:** the earliest pending time > now across events that haven't ended, together with `pausedUntil` if it's in the future.

  - `nextFireDateIsEarliestPending`: at 09:00 → 09:50; after firing at 09:50 → 09:59.
  - `catchUpAfterSleepShowsOnce`: the first evaluation is at 09:59:30 with both times past → shown once. After `markFired(at: 09:59:30)`, 09:59:45 shows nothing.
